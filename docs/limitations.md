# Scope and remaining limitations

Implemented: secure owner bootstrap (production setup token), Argon2id sessions/roles/CSRF/rotation/revocation; encrypted HTTP credentials and webhook secrets; durable monitoring, hysteresis, incidents, alerts and real agent discovery; Discord embed editing/preview and routing/cooldowns; resources with audited expiring overrides; branded SSR public pages with configurable tabs, editorial incidents, maintenance and RSS; HTTPS Compose profile and guarded backup/restore scripts.

The following are not implemented or deliberately bounded:

- No ICMP, arbitrary process/systemd checks, Telegram, emailed reset tokens. SMTP *monitoring* checks a greeting; email notification channels use an operator-configured STARTTLS submission server, and recovery still uses the documented owner CLI. Optional per-user SHA-256 TOTP is available; CLI password recovery clears it.
- Redis/SMTP/PostgreSQL probes check fixed unauthenticated protocol responses, not application-level query success. TLS checks validate the certificate chain and expiry; HTTP can optionally follow up to three redirects, resolving and checking each target against the address policy and sending saved credentials only to the original origin. DNS expected matching compares complete textual records, not semantic MX/SRV fields.
- Channels support UTC quiet hours, a delayed DOWN message and repeat reminders for open incidents after the first DOWN delivery succeeds. A monitor can name one parent dependency; child DOWN delivery waits while that parent is DOWN, while child incidents and telemetry continue. No multi-step escalation policy editor. Network checks support 0–3 retries within each observation; scheduled consecutive observations still provide hysteresis. DEGRADED routing/templates exist, but automatic resource-threshold checks currently produce UP/DOWN. Delivery is at least once; a crash after provider acceptance can duplicate a message.
- Manual resources have no measured uptime unless backed by monitors. Overrides are visibly labeled and never change telemetry. Multiple linked monitors use duration-weighted measured coverage, not an invented historical composite service state. Resource status history is audited; it is not a separate public time-series chart.
- Incident publication is explicit per page; raw automatic failures never publish themselves. Public status-page email subscriptions require configured SMTP and deliver only editorial incident changes; no subscriber SMS or localization editor, custom HTML/CSS or automatic custom-domain certificates/mapping. Custom tabs are escaped plain text. Logos/support are HTTPS URLs and can disclose visitors' requests to the operator-selected host.
- Public projection supports at most 500 selected distinct monitors with bounded recent check histories, 200 incidents and 100 updates per incident. Public refresh is 30 seconds. Admin monitor APIs paginate to 500 per request; the monitor list has server-side search, state/type filtering and 500-item page controls, while UI editors still show the latest 500 definitions and summaries the latest 100. Global health counts cover all definitions. Large installations still need pagination in editors, query/storage budgeting and load testing.
- Raw checks default to 90 days of retention, configurable per monitor from 7–365 days with hourly pruning. No long-term downsampling or full-period latency percentiles. Displayed p50/p95 describe latest samples. Agent CPU/RAM/disk percentages are retained in five-minute buckets for 90 days and charted over 1, 7 or 30 days; network values remain latest snapshots. Docker metrics/log streaming and discovery bulk synchronization are absent.
- No multi-tenant isolation, active-active scheduler, automatic upgrades or complete OpenAPI schema. An internal bearer-protected Prometheus exporter exposes aggregate monitor and delivery gauges. Use one active API per trusted workspace. DB availability is required; the advisory-lock connection loss stops the API safely.
- A native API systemd unit and environment template are supplied, but end-to-end native deployment and real public ACME certificate issuance require operator machines/DNS. Container agent metrics can reflect namespaces/cgroups. Docker socket access is host-equivalent privilege even through a read-only mount; use an explicitly restricted local API proxy where appropriate.
- No real Discord webhook or SMTP account was supplied. Local protocol-shaped mocks verify webhook delivery, retry, template payloads and mention suppression. Actual vendor delivery requires your configured destination.

A server cannot announce its own complete outage. Run the control plane or an independent observer on another machine, and add host monitors for missed-heartbeat detection. Monitoring always runs in Rust independent of browser tabs.

Push heartbeat grace is separately editable in seconds (default: one additional check interval). Public tabs use shareable hash links; SEO content defaults to the first configured tab. Onboarding and settings use functional individual workflows rather than a guided multi-step wizard.
